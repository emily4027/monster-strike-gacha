# 📊 怪物彈珠 - 抽蛋統計工具 (Monster Strike Gacha Tracker)

🔗 **線上使用**：https://emily4027.github.io/monster-strike-gacha/

🧰 **工具箱首頁**：https://emily4027.github.io/monster-strike-toolbox/

為《怪物彈珠》玩家設計的統計工具，用來記錄、管理並分析各個帳號在不同活動中的抽蛋投入狀況。提供歷史紀錄、統計儀表板、備份，並可透過 Google 登入進行雲端同步。

---

## ✨ 主要功能

### 📝 紀錄管理
- **雙模式介面**：
  - 檢視模式：純瀏覽數據，防止誤觸修改。
  - 編輯模式：解鎖表單與表格上的編輯 / 刪除按鈕。
- **彈性錄入**：
  - 新活動或新帳號可直接在選單選擇「-- 新增 --」建立，不需切換頁面。
  - 選擇活動時，會自動帶入該活動的日期與標籤（資料來自活動清單或你的歷史紀錄）。
  - **活動標籤**：本家、合作、免費、寶珠，表格左側會以不同色條標示；標籤為「免費」或「寶珠」且未填抽數時，預設為 0 抽。
  - **重複防呆**：同一天、同一活動、同一帳號不能重複建立紀錄。
- **獲得角色自動標準化**：輸入時可用頓號、逗號、空白、加號或換行分隔，儲存時會自動整理成 `角色*數量`，例如 `亞森 x2 尼奧、2隻杏子` → `亞森*2、杏子*2、尼奧`。
  - 數量可以寫在名稱後面（`亞森*2`、`亞森x2`、`亞森 2隻`）或前面（`2*亞森`、`2隻亞森`、`2亞森`），中間有空格、全形數字也可以；單獨的 `*2` 代表前一個角色乘以 2。
  - 數字直接放在名稱前面時，名稱要有 2 個字以上，所以 `2B`、`9S` 會保留為名稱；名稱後面直接接數字（`亞森5`）視為名稱的一部分。
  - 同名角色會合併、依數量由多到少排序；標籤為「寶珠」時，純數字會自動補上「顆」。紀錄編輯區塊右上角的「格式教學與範例」按鈕有詳細說明。
- **智能編輯**：
  - **單筆編輯**：修正特定帳號的抽數或備註。
  - **批次更新**：若活動名稱、日期或標籤有誤，可一次更新該活動所有帳號的紀錄。

### 📈 統計儀表板
- **篩選條件**（可交叉使用）：
  - 帳號。
  - 日期範圍：年份與月份合併在同一個選單，月份旁會標出當月的合作活動。
  - 活動類型：本家 / 合作 / 免費 / 寶珠，可多選。
- **即時統計**：總投入抽數、各帳號總抽數（由多到少）、各活動總抽數（依時間由新到舊，可滾動瀏覽）。
- **每隻平均抽數**：本家與合作活動會顯示抽到幾隻角色、平均每隻幾抽。角色數從「獲得角色」計算，`亞森*2、尼奧` 算 3 隻；「無」、純數字、「3抽」「11顆」不算角色。
- **每月投入趨勢**：每個月投入的抽數長條圖。
- **活動類型比例**：本家／合作／免費／寶珠各占總抽數的比例。

### ☁️ 雲端同步 (Google 登入)
- 登入 Google 帳號後，紀錄會自動儲存到雲端（編輯後約 1.5 秒），可在不同裝置存取；頁首的狀態燈號會顯示「雲端 / 儲存中 / 離線」。
- 未登入或雲端無法連線時，自動使用瀏覽器 LocalStorage，不影響使用。
- 登入後以**雲端資料為準**；只有雲端尚無資料時，才會把本機紀錄上傳。如果本機留著的紀錄可能屬於另一個帳號，會先跳出確認，由你決定是否上傳。未登入時建立的紀錄若因雲端已有資料而沒有上傳，會先自動下載一份備份。
- **多裝置 / 多分頁**：存檔前會先比對雲端紀錄的版本號，確認有沒有被其他裝置改過；改過的話會自動合併兩邊的修改（三方合併），不會互相覆蓋。同一筆紀錄兩邊都改過時，以正在存檔的這台為準；一邊刪除、另一邊修改時，保留修改後的紀錄。
- **雲端暫時連不上**：修改會先存在這台電腦，下次成功連上雲端時自動合併上傳。
- **登出**：登出前會先送出尚未儲存的變更；若仍有修改存不到雲端，會先詢問並下載備份。登出後會清除這台電腦上的紀錄（畫面與 LocalStorage），雲端資料不受影響，再次登入即可取回。從未登入、只在本機使用的紀錄不會被清除。

### 🗓 活動清單
- 活動選單會合併「官方活動清單」與你自己的歷史紀錄。
- 活動清單由管理員維護並存放在雲端，開啟頁面時自動取得最新內容；讀取不到時改用 `events.json` 備援。
- 活動若被更名，所有人的紀錄會自動對應到新名稱，不需要手動修改。
- 活動可以有結束日（選用），[活動行事曆](https://emily4027.github.io/monster-strike-event-calendar/)會把有結束日的活動畫成期間。
- 每天台灣時間中午 12:00，活動行事曆 repo 的爬蟲會抓官網的轉蛋公告，自動把新活動加進清單（含結束日與公告網址）。

### 💾 資料安全與遷移
- **備份與還原**：點「下載備份」將所有紀錄匯出成 JSON，點「載入備份」從備份檔還原，方便在裝置間轉移。載入的內容會**取代**目前所有紀錄，載入前會先跳出確認；載入時也會檢查格式，格式不正確的紀錄會被略過並提示。
- **資料清除**：「初始化資料」可一鍵清除所有紀錄（有防呆確認）。登入狀態下，雲端的紀錄也會一併清除。

### 🎨 介面設計
- 基於 Bootstrap 5 客製化的卡片式介面。
- 操作時有 Toast 訊息提示（成功 / 錯誤 / 資訊）。
- RWD：手機與電腦皆可使用。
- 懸浮工具箱可快速前往其他工具。工具清單讀取[工具箱](https://github.com/emily4027/monster-strike-toolbox)的 `tools.js`，工具箱新增工具時會自動出現；讀不到時使用 `index.html` 裡的連結。

## 🚀 如何使用

### 1. 開始使用
開啟網頁即可使用。想要雲端同步，點頁首的「登入 Google 帳號以啟用雲端功能」。

### 2. 新增紀錄
1. 點擊表單右下角的「檢視模式 (點此編輯)」，切換成編輯模式。
2. 選擇日期、活動（或選「-- 新增活動 --」自行輸入）、標籤、帳號（或按帳號欄旁的 ✏️ 輸入新帳號）。
3. 填寫投入抽數與獲得角色，點擊「儲存紀錄」。

### 3. 編輯 / 修正
- **單筆**：在下方表格點擊黃色鉛筆按鈕，資料會帶入上方表單，修改後點「更新紀錄」。
- **整個活動**：選擇活動後按活動欄旁的 ✏️，帳號選「-- 全部帳號 (僅編輯) --」，即可一次修改該活動所有帳號的名稱、日期或標籤。

### 4. 查看統計
使用中間的儀表板，切換帳號、日期範圍與活動類型，下方的總數與列表會即時更新。

## 🔧 活動清單維護 (管理員)

活動清單存放在 Firestore，只有管理員能修改：

- **管理員判斷**：Firestore 中存在 `admins/{使用者 uid}` 文件的帳號即為管理員（文件由專案擁有者在 Firebase Console 手動建立）。登入後頁面會顯示「管理員模式」，並出現管理功能。
- **權限把關**：寫入權限由 Firestore 安全規則控制，前端的判斷只用來顯示或隱藏按鈕。
- **`events.json`**：作為備援與初始資料。雲端活動清單有資料時，以雲端為準。
- **管理功能位置**：
  - 紀錄編輯區塊：「儲存活動到清單」「從清單刪除活動」。
  - 資料管理：「匯入活動清單」「匯出活動清單」。

### 常用操作
- **新增活動**：進入編輯模式，活動名稱選「-- 新增活動 --」，填名稱、日期、標籤，按「儲存活動到清單」。
- **修改日期或標籤**：選活動，按 ✏️，修改後按「儲存活動到清單」（不要按「更新紀錄」，那只會改自己的紀錄）。
- **更名**：同上，改名稱後按「儲存活動到清單」。舊名稱會自動記為別名，所有人的紀錄會對應到新名稱。
- **刪除**：選活動，按「從清單刪除活動」。只移除清單，不會刪除任何人的紀錄。爬蟲加的活動刪掉後不會再被加回來。
- **結束日**：管理員模式下表單會多一個「活動結束日」欄位（選用），按「儲存活動到清單」才會存；清空再儲存就是移除結束日。只影響活動清單，不影響任何人的紀錄。
- **爬蟲自動新增的活動**：名稱為 `YYYY-MM月 轉蛋名稱`，標籤依公告標題判斷（合作 / 免費 / 其他都當本家，不會自動標寶珠）。判斷錯了照上面的方法修改即可；改名後舊名稱會記為別名。官網沒有另外發公告的轉蛋（例如部分免費轉蛋）抓不到，仍要手動新增。
- **存檔時清單剛被改過**：存檔前會比對雲端清單的更新時間，和開啟後讀到的不同（例如爬蟲剛新增了活動、或其他管理員改過）就不寫入，並重新載入清單，避免把別人新增的活動蓋掉。確認後再操作一次即可。
- **首次建立雲端清單**：按「匯入活動清單」，選擇 repo 裡的 `events.json`。已存在的活動不會被覆蓋。
- **更新備援檔**：按「匯出活動清單」，下載的檔案覆蓋 repo 裡的 `events.json`。

### `events.json` 格式
```json
{
  "event": "2025-03月 Code Geass 反叛的魯路修",
  "date": "2025-03-15",
  "endDate": "2025-03-31",
  "tag": "collab",
  "aliases": ["2024-03月 Code Geass 反叛的魯路修"]
}
```

| 欄位 | 說明 |
|------|------|
| `event` | 活動名稱，建議以 `YYYY-MM月` 開頭，方便排序 |
| `date` | 活動開始日期 `YYYY-MM-DD` |
| `endDate` | （選用）活動結束日期 `YYYY-MM-DD`，不能早於 `date`。舊資料沒有這個欄位也沒關係 |
| `tag` | `honke`（本家）、`collab`（合作）、`free`（免費）、`orb`（寶珠） |
| `aliases` | （選用）舊名稱清單；活動更名後，舊名稱的紀錄會自動對應到新名稱 |
| `source` | （選用）爬蟲加的活動會記錄官網公告網址，用來避免重複新增 |

雲端的 `shared/events` 文件內容是 `{ events: [上面格式的活動…], updatedAt }`。寫入者有兩個：這裡的管理員介面，和活動行事曆的爬蟲（以 service account 寫入，只新增活動、補上缺少的結束日）。兩邊寫入時都會更新 `updatedAt`。

## 🧩 開發筆記

`script.js` 依區塊整理：設定與常數 → DOM 與狀態 → 工具函式 → 雲端與登入 → 存檔 / 讀取 → 角色格式化與活動清單 → 渲染 → 表單模式 → 事件綁定 → 啟動。

不碰畫面與 Firebase 的純函式放在獨立檔案，有自動化測試：
- `sync.js`：版本比對與三方合併（`window.GachaSync`）。
- `notes.js`：獲得角色字串的格式化與計算隻數（`window.GachaNotes`）。果實分配也會解析這個格式，改格式化規則時要一起確認果實分配。

**Firestore 資料路徑**

| 路徑 | 內容 | 讀寫權限 |
|------|------|----------|
| `artifacts/{appId}/users/{uid}/data/gacha_records` | 使用者的抽卡紀錄 (`records`、`version`、`lastUpdated`) | 僅本人 |
| `shared/events` | 活動清單 | 所有人可讀，管理員可寫 |
| `admins/{uid}` | 管理員名單 | 僅本人可讀，前端不可寫 |

`appId` 未提供時為 `default-app-id`。

**紀錄文件的欄位**（`gacha_records`）

| 欄位 | 說明 |
|------|------|
| `records` | 紀錄陣列，每筆有 `id`、`date`、`event`、`account`、`pulls`、`notes`、`tag` |
| `version` | 每次寫入加 1，用來偵測其他裝置的修改 |
| `lastUpdated` | 最後寫入時間 |

**寫入規則**（抽卡統計與果實分配都要遵守）：
- 在 transaction 裡讀取文件，`version` 或 `lastUpdated` 和上次讀到的不同，就代表被其他裝置改過，要先合併再寫入。只比對是否相同，不比先後，電腦時間不準也不影響。
- 寫入時 `version` 加 1、更新 `lastUpdated`，並使用 `{ merge: true }`。
- 三方合併比對紀錄 `id` 以外的所有欄位，新增欄位不需要另外修改合併程式。讀取紀錄時會保留不認識的欄位，舊版頁面存檔不會把新欄位刪掉。

**和果實分配共用的資料**：果實分配會讀取這份紀錄文件，把抽到的角色匯入成果實分配的角色。
- **紀錄 `id` 不能更改**：果實分配用紀錄 `id` 記住每隻角色是從哪一筆紀錄匯入的，`id` 一變對應就會斷掉。抽卡統計只在讀到沒有 `id` 或 `id` 重複的紀錄、以及兩台裝置剛好新增了相同 `id` 的紀錄時，才會換新的 `id`。
- **會讀取的欄位**：`id`、`account`、`date`、`event`、`tag`、`notes`（`tag` 為 `orb` 的紀錄會略過）。
- **果實分配會改寫 `notes` 欄位裡的角色名稱**：使用者在果實分配選擇統一名字時，會依上面的寫入規則改寫所有帳號紀錄中的角色名稱。因此 `notes` 的格式（`角色*數量`，以頓號分隔）要和果實分配的解析方式保持一致。

**本地開發**：因為使用 Firebase，請透過本機伺服器開啟，不要直接用 `file://`：

```bash
python -m http.server 8000     # 然後開啟 http://localhost:8000
# 或使用 VS Code 的 Live Server 擴充功能
```

**自動化測試**：需要 Node.js 18 以上，不用安裝任何套件。修改 `sync.js` 或 `notes.js` 後執行：

```bash
node --test tests/
```

## 📝 注意事項

- **瀏覽器資料**：未登入時資料只存在瀏覽器中，清除瀏覽器資料可能導致遺失，請定期使用「下載備份」。
- **活動名稱格式**：系統會自動簡化顯示名稱（例如隱藏與日期重複的年月），建議輸入完整名稱（如 `2025-10月 鬼滅之刃合作`）以利排序。
- **多裝置使用**：請在各裝置登入同一個 Google 帳號。登入後以雲端資料為準。
- **登出會清除本機紀錄**：登入過的帳號登出後，這台電腦上的紀錄會被清除；若想在登出後離線使用，請先「下載備份」。
